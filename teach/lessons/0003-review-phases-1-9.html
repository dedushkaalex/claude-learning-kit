Один конкретный результат: после урока ты по любому фрагменту из src/ называешь A, E, R, говоришь, что перезапустится в атомах после действия, и объясняешь, почему ошибка попала в E, а не стала дефектом.

Связь с проектом: фазы 1–9 из learning/curriculum.md, код в src/server/todo/, src/entities/todo/, src/features/todos/. Новых тем в уроке нет. Термины: глоссарий.

1. Как проходить этот урок

Материал уже пройден, поэтому цель другая: удержать его надолго, а не узнать заново. Для этого работает припоминание без подсказки. Порядок такой.

  1. Открой карточку, ответь вслух, потом нажми «Показать ответ». Ответ до раскрытия обязателен, иначе упражнение не работает.
  2. Отметь «Вспомнил сам» или «Не вспомнил». Отметки сохраняются в браузере.
  3. Через два дня открой урок снова и пройди только карточки с отметкой «Не вспомнил».
  4. Через неделю сбрось отметки и пройди все карточки.

Карточки перемешаны по фазам намеренно. Один вопрос по слоям, следующий по атомам, потом по ошибкам. Так проверяется выбор инструмента, а не память на порядок уроков.

Проверка 1: тип ошибки до transportAsDefect

В src/entities/todo/todoClient.ts метод create собран как client.todo.create({ payload: { title } }).pipe(transportAsDefect). Запиши, какие теги будут в E у client.todo.create(...) до pipe. Потом временно добавь строку ниже внутри make, выполни pnpm typecheck и прочитай первую ошибку.

const probe: never = client.todo.create({ payload: { title: "" } })
Ответ

EmptyTitle | TitleTooLong из контракта, плюс HttpClientError и SchemaError от клиента, плюс TimeoutError, потому что makeWith получил HttpClient с Effect.timeout. После transportAsDefect остаются только EmptyTitle | TitleTooLong. Строку с probe удали и снова выполни pnpm typecheck.

Проверка 2: сколько запросов уходит после toggle

Запусти сервер и приложение (pnpm dev:server, pnpm dev), открой вкладку Network в Chrome, включи Slow 3G. Запиши, сколько запросов GET /todos уйдёт после одного клика по галочке и в какой момент по отношению к PATCH.

Ответ

Один GET /todos, после успешного PATCH /todos/:id/toggle. Галочка при этом переключается сразу, до PATCH. Два GET означают, что внутренний runtime.fn получил reactivityKeys.

Проверка 3: id расходуется до проверки заголовка

Открой src/server/todo/__tests__/todoService.test.ts, блок layer(testLayer)("createTodo", ...). В нём три теста: первый создаёт todo и ожидает todo-0, второй вызывает createTodo(" ") и ожидает EmptyTitle, третий вызывает toggleTodo с несуществующим id. Запиши, какой id получит четвёртый тест, если добавить его в конец блока и создать в нём todo с нормальным заголовком. Потом добавь такой тест временно, выполни pnpm test, прочитай id из сообщения об ошибке или из expect, и удали тест.

Ответ

todo-2. Слой общий на блок, счётчик один. Второй тест тоже расходует id: в newTodo строка yield* idGenerator.next стоит раньше validateTitle(title), и генератор доходит до ошибки уже после получения todo-1. Третий тест id не расходует: toggleTodo не вызывает newTodo. Ответ todo-1 означает, что порядок yield* в newTodo не учтён.

Жизненный цикл атома и освобождение ресурсов

Шпаргалка по атомам в effect@4.0.0-rc.112. Сверено с установленным исходным кодом и пробным тестом реестра 07.09.2026.

Таймлайн одного размонтирования

  1. Выполняется очистка компонента, useAtomMount отписывается. Счётчик подписчиков падает до 0.
  2. Реестр планирует проверку в следующей задаче (scheduleNodeRemoval, задержка 0). Ничего ещё не разобрано.
  3. Всё, что выполняется до этой задачи, включая повторное монтирование в том же коммите React, может подписаться снова.
  4. Задача выполняется. Если canBeRemoved всё ещё истинно, узел удаляется: Scope атома закрывается, выполняется release из acquireRelease, файбер прерывается. Иначе атом остаётся как есть.

Правила на каждый день

  • Клади ресурс в атом, а не в useEffect, когда его жизнь должна совпадать с «кто-то смотрит на эти данные», а не с «этот компонент существует».
  • release обязан возвращать Effect; голый void ломает вывод типов и проявляется как R = unknown.
  • Ключ сервиса (Reactivity.Reactivity) это не сам сервис: один раз сделай yield* и замыкай значение в обработчиках.
  • Ref.make(0) на уровне модуля всё ещё эффект: каждый yield* создаёт новую ячейку. Для одной ячейки на модуль есть Ref.makeUnsafe.

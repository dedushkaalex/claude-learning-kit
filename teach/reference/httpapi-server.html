HttpApi-сервер в effect@4.0.0-rc.112

Проверено на todo-сервере 08.09.2026: модули effect/unstable/httpapi, effect/unstable/http, @effect/platform-node.

Контракт

ЧтоКак
ЭндпоинтHttpApiEndpoint.get | post | patch | put | delete("name", "/todos/:id", { params, query, payload, success, error })
paramsЗапись полей: { id: TodoId }. Параметр может стоять в середине пути: /todos/:id/toggle.
payloadДля методов с телом только схема: Schema.Struct({ title: Schema.String }). Валидацию оставляй домену, иначе объявленные ошибки недостижимы.
successСхема ответа. По умолчанию HttpApiSchema.NoContent (204). Возвращай то, что вернул use case.
errorСхема или массив схем. Статус через HttpApiSchema.status(404)(TodoNotFound) на той схеме, что передана сюда. Без аннотации будет 500.
СборкаHttpApi.make("todoApi").add(HttpApiGroup.make("todo").add(e1, e2, ...))
Проверка контрактаOpenApi.fromApi(api) → пути, методы, статусы ответов.

Обработчики

export const todoHandlersLayer = HttpApiBuilder.group(todoApi, "todo", (handlers) =>
  handlers
    .handle("todos", () => Effect.flatMap(TodoRepository, (r) => r.all))
    .handle("create", ({ payload }) => createTodo(payload.title))
    .handle("remove", ({ params: { id } }) => removeTodo(id)),   // success NoContent → обработчик возвращает void
)
  • Аргумент обработчика: { params, payload }, уже декодированные.
  • E обработчика обязан входить в объявленные ошибки эндпоинта, иначе слой не соберётся.
  • Сервисы из R обработчиков попадают в тип слоя как HttpRouter.Request<"Requires", …>.

Запуск

const api = HttpApiBuilder.layer(todoApi, { openapiPath: "/docs/openapi.json" }).pipe(
  Layer.provide(todoHandlersLayer),                     // до serve
)
const app = HttpRouter.serve(api).pipe(
  Layer.provide(services),                              // после serve
  Layer.provide(NodeHttpServer.layer(createServer, { port })),
)
NodeRuntime.runMain(Layer.launch(app))

Запуск в проекте: pnpm dev:server (tsx с --tsconfig tsconfig.server.json, иначе алиас @/ не разрешится).

Значение Effect и способы его собирать

Effect<A, E, R>
Описание вычисления, которое ещё не запущено. A — тип успешного результата, E — тип ожидаемой ошибки, R — сервисы, которые нужны перед запуском. Само значение ничего не делает, пока его не запустит runtime. В проекте: src/server/todo/todoRules.ts, findTodo имеет тип Effect<Todo, TodoNotFound, never>. Не путать с: Promise. Promise запускается в момент создания, ошибки в его типе не видны.
Ленивое значение (lazy value)
Значение, которое описывает работу, но не выполняет её. Один и тот же Effect можно запустить дважды, и работа выполнится дважды. В проекте: TodoIdGenerator.layer в todoIdGenerator.ts. Поле next — один объект Effect.sync(...), но каждый yield* idGenerator.next даёт новый id.
Runtime (среда выполнения)
То, что запускает Effect и отдаёт результат наружу. В тестах это it.effect, в приложении Atom.runtime, в скрипте Effect.runPromise или NodeRuntime.runMain. В проекте: src/entities/todo/todoRuntime.ts, src/server/main.ts.
Канал (channel) A, E, R
Три позиции в типе Effect. Операции делятся по каналу, на который действуют: Effect.map меняет A, Effect.mapError меняет E, Effect.provide убирает из R.
Effect.gen и yield*
Генератор, в котором yield* перед эффектом достаёт его A, а E и R этого эффекта добавляются в тип всего генератора. Если эффект под yield* завершился ошибкой, генератор останавливается на этой строке. В проекте: newTodo в todoRules.ts, четыре yield* подряд.
Effect.fn
Обёртка над генератором с параметрами. Даёт функцию, которая возвращает Effect, и присваивает вызову имя для трассировки. В проекте: Effect.fn("addTodo")(function* (todos, title) { ... }) в todoRules.ts. Ошибка из learning/mistakes.md: (title) => Effect.fn(...)(function* () {}) возвращает функцию, а не эффект. Параметры ставятся на генератор.
Span
Именованный отрезок трассировки. Имя, переданное в Effect.fn("createTodo"), попадает в трассу каждого вызова. Скопированное имя из другого use case даёт неверную трассу.
pipe
Передача значения через цепочку функций слева направо: a.pipe(f, g) равно g(f(a)). У каждого шага виден только результат предыдущего. В проекте: validateTitle в todoRules.ts.
Effect.map / Effect.flatMap / Effect.tap
map: callback возвращает обычное значение, оно становится новым A. flatMap: callback возвращает Effect, он выполняется следующим. tap: callback выполняется ради побочного действия, A не меняется. В проекте: Effect.flatMap(TodoClient, (client) => client.todos()) в todoStore.ts. Ошибка из learning/mistakes.md: Effect, возвращённый из callback функции map или sync, не выполняется, а попадает в A как данные.
Effect.sync / Effect.succeed
succeed(value) оборачивает готовое значение. sync(() => value) откладывает вычисление до запуска. Побочное действие (crypto.randomUUID(), new Date()) ставится в sync, иначе оно выполнится один раз при создании эффекта. В проекте: Effect.sync(() => TodoId.make(crypto.randomUUID())) в todoIdGenerator.ts.
Short-circuit (остановка на первой ошибке)
Поведение генератора: yield* на упавшем эффекте прекращает выполнение всех следующих строк, и весь эффект завершается той же ошибкой. Ошибка не «обрабатывается внутри», она передаётся наверх. В проекте: в renameTodo из todoRules.ts после yield* findTodo(todos, id) с ошибкой TodoNotFound строка с validateTitle не выполняется.
Fiber
Единица выполнения одного запущенного эффекта. Fiber можно прервать (interrupt) и дождаться (join). runtime.fn прерывает предыдущий fiber того же атома, если атом записан повторно.

Ошибки: ожидаемые и дефекты

Ожидаемая ошибка (expected error)
Исход, который вызывающий код может обработать. Записывается в канал E. Критерий: есть ли у вызывающего кода осмысленное действие при этой ошибке. В проекте: EmptyTitle, TitleTooLong, TodoNotFound в src/entities/todo/types.ts.
Дефект (defect)
Сбой, который вызывающий код обработать не может: ошибка программиста или отказ инфраструктуры без плана восстановления. В канале E не виден. Создаётся через Effect.die или Effect.orDie. В проекте: transportAsDefect в todoClient.ts превращает HttpClientError, SchemaError, TimeoutError в дефекты.
Schema.TaggedError
Класс ошибки с полем _tag и типизированными полями. Экземпляр можно поставить под yield*, и он попадёт в E. Тот же класс кодируется в JSON и восстанавливается на клиенте. В проекте: class TodoNotFound extends Schema.TaggedError<TodoNotFound>()("TodoNotFound", { id: TodoId }).
_tag
Строковое поле, по которому различаются варианты в объединении типов. По нему работают Effect.catchTag, AsyncResult.builder.onErrorTag, Match.
Effect.catchTag
Обрабатывает ошибку с указанным _tag и убирает её из E. Остальные ошибки проходят дальше. Callback возвращает Effect с заменой. В проекте: Effect.catchTag("SchemaError", () => ...) в todoRepository.ts.
Effect.mapError
map для канала E: callback получает ошибку и возвращает новую ошибку как обычное значение. В проекте: validateTitle в todoRules.ts заменяет SchemaError на EmptyTitle или TitleTooLong.
Effect.flip
Меняет местами A и E. В тесте yield* Effect.flip(effect) даёт ошибку как значение, и её можно проверить через expect.
Effect.orDie
Переводит все ошибки из E в дефекты. После него E = never. Применяется там, где восстановление невозможно или бессмысленно. В проекте: save в TodoRepository.layerKeyValueStore.
Exit и Cause
Exit — итог запуска: Success с A или Failure с Cause. Cause хранит, что именно произошло: ожидаемая ошибка (Fail), дефект (Die) или прерывание (Interrupt). Cause.squash достаёт из Cause одно значение ошибки.

Schema: описание данных

Schema
Значение, которое описывает форму данных и умеет проверять, декодировать и кодировать их. Из одной схемы выводится тип TypeScript. В проекте: Todo, Title, TodoId в types.ts.
Type и Encoded
Две стороны схемы. Type — значение в памяти программы. Encoded — значение после кодирования, то, что уходит в JSON или localStorage. В проекте: Schema.DateFromString в поле createdAt: Type = Date, Encoded = string. Не путать с: v3 Schema.Date преобразовывал строку в Date. В v4 Schema.Date описывает Date с обеих сторон.
Декодирование (decode) и кодирование (encode)
decode: из Encoded в Type с проверками. encode: обратно. Домен работает только с Type. Кодирует репозиторий на границе с хранилищем или сетью.
Schema.decodeEffect, decodeUnknownEffect, decodeSync
Семейство функций декодирования. Часть Unknown в имени означает, что вход имеет тип unknown. Суффикс задаёт обёртку результата: Effect, Sync (исключение при ошибке), Option, Result. В проекте: Schema.decodeEffect(Title)(title) в todoRules.ts.
Schema.make (метод .make)
Проверяет значение, уже имеющее тип Type, и возвращает его с брендом. При нарушении бросает исключение, то есть дефект. Не декодирует. В проекте: TodoId.make(crypto.randomUUID()) в todoIdGenerator.ts.
Schema.brand (брендированный тип)
Добавляет к базовому типу метку, из-за которой обычная string не подходит туда, где ожидается TodoId. Проверка на этапе компиляции, в runtime значение остаётся строкой. В проекте: Schema.String.pipe(Schema.brand("TodoId")).
Schema.Trim.check(...)
Trim — преобразование, которое обрезает пробелы при декодировании. check добавляет проверки: Schema.isNonEmpty(), Schema.isMaxLength(100). В проекте: схема Title в types.ts.
Schema.Struct, Schema.Array, Schema.Union, Schema.Literals
Составные схемы: объект с полями, массив, объединение вариантов, набор строковых литералов. В проекте: Schema.Literals(["all", "active", "completed"]) в src/features/todos/model/filter.ts.
SchemaError
Ошибка декодирования или кодирования. При чтении из хранилища это ожидаемая ошибка (данные могли испортиться). При записи это дефект (кодируется значение, которое программа сама создала).

Сервисы и слои: канал R

Сервис (service)
Именованная зависимость, которую эффект получает из контекста при запуске. Состоит из ключа и реализации. В проекте: TodoRepository, TodoIdGenerator, TodoClient.
Ключ сервиса (service key) и реализация
Ключ — класс, созданный через Context.Service. Реализация — объект нужной формы, который лежит в контексте под этим ключом. yield* TodoRepository возвращает реализацию и добавляет ключ в R. Повторяющаяся ошибка из learning/progress.md: обращение к ключу (Clock.Clock, Reactivity) как к самой реализации.
Context.Service<Self, Shape>()("name")
Создаёт класс-ключ с формой реализации Shape. Слои пишутся вручную, статическими полями класса. В проекте: class TodoIdGenerator extends Context.Service<TodoIdGenerator, { readonly next: Effect.Effect<TodoId> }>()("app/TodoIdGenerator"). Не путать с: v3 Effect.Service, у которого был автоматический слой .Default.
Context.Reference (сервис со значением по умолчанию)
Ключ, у которого есть defaultValue. Обращение к нему не добавляет ключ в R. Так устроены Clock и ConfigProvider. В проекте: DateTime.nowAsDate в newTodo читает Clock, и R от этого не растёт.
Layer<Out, E, In>
Рецепт сборки сервисов. Out — что слой даёт, In — что ему нужно для сборки, E — ошибка сборки. В проекте: TodoRepository.layerKeyValueStore имеет In = KeyValueStore.
Layer.succeed / Layer.effect
succeed(Key, impl) кладёт готовый объект. effect(Key, effect) собирает реализацию эффектом: можно создать Ref, прочитать Config, взять другой сервис. В проекте: TodoIdGenerator.layer и TodoIdGenerator.layerTest.
Effect.provide / Layer.provide / Layer.provideMerge
Effect.provide(effect, layer) убирает Out слоя из R эффекта. Layer.provide(outer, inner) закрывает In внешнего слоя внутренним; наружу виден только Out внешнего. Layer.provideMerge делает то же, но наружу виден и Out внутреннего. В проекте: TodoClient.layer.pipe(Layer.provide(FetchHttpClient.layer)) в todoRuntime.ts.
Layer.merge
Складывает два независимых слоя в один: Out объединяются, In объединяются. В проекте: Layer.merge(todoClientLayer, KeyValueStore.layerStorage(...)).
Мемоизация слоёв (layer memoization) и Layer.fresh
Внутри одного runtime слой собирается один раз, повторное provide того же значения слоя переиспользует экземпляр. Layer.fresh(layer) заставляет собрать заново. В проекте: тест в src/server/todo/__tests__/todoRepository.test.ts, пара «общий экземпляр» и «Layer.fresh».
Ref
Изменяемая ячейка. Чтение и запись — эффекты: Ref.make, Ref.get, Ref.set, Ref.getAndUpdate. Ref.make под yield* каждый раз создаёт новую ячейку. В проекте: счётчик в TodoIdGenerator.layerTest, список в TodoRepository.layerMemory.
Clock и TestClock
Clock — сервис времени со значением по умолчанию (системные часы). it.effect подменяет его на TestClock, время стоит на нуле и двигается только через TestClock.adjust или TestClock.setTime.
Config и ConfigProvider
Config.string("KEY") — эффект чтения настройки через сервис ConfigProvider. По умолчанию провайдер читает переменные окружения. ConfigProvider.layer(ConfigProvider.fromEnvRecord({...})) подменяет источник. В проекте: browserConfig в todoRuntime.ts, Config.string("TODO_API_URL").pipe(Config.withDefault("")) в todoClient.ts.
Точка сборки (composition root, «граница runtime»)
Единственное место, где конкретные слои соединяются с приложением. Модули домена и фич не знают, какой репозиторий или клиент им подали. В проекте: src/entities/todo/todoRuntime.ts для браузера, src/server/main.ts для сервера.

Тесты с @effect/vitest

it.effect
Тест, тело которого — эффект. Запускается под TestClock. Любое ожидание по времени (Effect.sleep, Schedule, Effect.timeout) стоит, пока тест не вызовет TestClock.adjust.
it.live
То же, но с настоящими часами. Используется, когда в тесте есть retry со Schedule и двигать время вручную не нужно. В проекте: тест retry в src/entities/todo/__tests__/todoClient.test.ts.
layer() и it.layer
Блок тестов с общим слоем. Слой собирается один раз на весь блок, поэтому Ref из Layer.effect общий для всех тестов внутри. Callback блока — обычная функция, а не эффект.
Effect.forkChild и Fiber.join
Запуск эффекта в отдельном fiber и ожидание его результата. Нужны в тесте таймаута: запустить вызов, сдвинуть TestClock, дождаться исхода.

Атомы и React: effect/unstable/reactivity, @effect/atom-react

Атом (atom)
Ячейка состояния с подписчиками. Компонент читает атом через hook и перерисовывается при изменении значения. Атом объявляется на уровне модуля. В проекте: src/entities/todo/todoStore.ts, src/features/todos/model/filter.ts.
Обычный атом: Atom.make(initial)
Хранит значение, доступное на чтение и запись. Аналог глобальной переменной с уведомлением подписчиков.
Производный атом (derived atom): Atom.make((get) => ...)
Функция от других атомов. Зависимости — всё, что прочитано через get. Пересчитывается при изменении любой из них. Ключи реактивности ему не нужны. В проекте: visibleTodosAtom и activeCountAtom в filter.ts.
Atom.runtime(layer)
Создаёт runtime для атомов и снабжает эффекты внутри них сервисами из слоя. Объявляется один раз на уровне модуля. Runtime внутри компонента создавался бы заново на каждый рендер. В проекте: export const runtime = Atom.runtime(Layer.merge(...)) в todoRuntime.ts.
runtime.atom(effect)
Атом, значение которого — результат эффекта в виде AsyncResult. Эффект выполняется при первой подписке и заново при инвалидации по ключу реактивности. В проекте: todosAtom в todoStore.ts.
runtime.fn(fn, options)
Атом-функция: при записи аргумента запускает эффект fn(arg), результат кладёт в свой AsyncResult. Повторная запись прерывает предыдущий fiber этого же атома. В проекте: createTodoAtom, renameTodoAtom, clearCompletedAtom. Форма без аргумента: runtime.fn<void>()(() => ...). Запись (_: void) => ... не даёт того же типа.
Ключ реактивности (reactivity key)
Строка, которой помечается атом-источник (Atom.withReactivity(["todos"])). runtime.fn с reactivityKeys: ["todos"] после успешного выполнения заставляет источники с этим ключом перечитать данные. Не путать с: зависимостью производного атома. Ключ обновляет источник, а get распространяет изменение вниз.
AsyncResult
Состояние асинхронного значения: Initial (ещё не было результата), Success, Failure. Флаг waiting отдельный: Success с waiting: true означает «есть старые данные, идёт перезапрос».
AsyncResult.builder
Способ описать разметку для каждого состояния: onInitial, onSuccess, onErrorTag("TodoNotFound", ...), onDefect. render() бросает исключение, если какая-то ветка не описана; orNull() возвращает null.
AsyncResult.map
Применяет функцию к значению внутри Success, остальные состояния пропускает без изменений. Так производный атом фильтрует список, не разворачивая AsyncResult вручную. В проекте: visibleTodosAtom.
useAtomValue / useAtom / useAtomSet
useAtomValue(atom) — только чтение. useAtom(atom) — пара «значение, запись». useAtomSet(atom) — только запись, компонент не перерисовывается при изменении значения. В проекте: useTodoList в src/features/todos/hooks/useTodoList.ts.
mode: "promise"
Опция для useAtom и useAtomSet с атомом-функцией. Функция записи возвращает Promise: успех со значением, отказ с самой ошибкой (Cause.squash). Нужна, когда обработчик события должен дождаться исхода и изменить локальное состояние React. В проекте: useTodoForm сбрасывает форму только после успешного create.
Atom.optimistic(source) (оптимистичная копия, mirror)
Записываемая копия атома-источника. Пока запрос идёт, копия показывает предполагаемый результат. Производные атомы читают копию, иначе UI не увидит предварительное значение. В проекте: optimisticAtom в todoStore.ts, его читают visibleTodosAtom и activeCountAtom.
Atom.optimisticFn(mirror, { reducer, fn })
Атом-функция с оптимистичным обновлением. reducer(current, input) вычисляет предварительное значение копии. fn — атом runtime.fn с самим запросом. При успехе источник перечитывается, при ошибке копия откатывается к последнему значению источника. Внутренний runtime.fn не должен нести reactivityKeys того же источника: будет двойной GET.
Atom.kvs({ runtime, key, schema, defaultValue })
Атом, значение которого сохраняется в KeyValueStore под ключом key через схему. В проекте: filterAtom в filter.ts.
Реестр атомов (registry)
Объект, который хранит значения атомов, подписки и решает, когда удалить атом без подписчиков. Подробности: справочник жизненный цикл атома.
StrictMode
Режим React для разработки: каждый эффект компонента выполняется дважды (setup, cleanup, setup). Выявляет отсутствующую очистку. В проекте включён намеренно.

Ресурсы и время жизни

Scope
Список финализаторов, которые выполняются при закрытии. runtime.atom создаёт Scope для своего эффекта и закрывает его, когда атом теряет последнего подписчика.
Финализатор (finalizer)
Эффект, зарегистрированный в Scope для выполнения при закрытии. Например, снятие обработчика события.
Effect.acquireRelease(acquire, release)
Выполняет acquire сейчас и регистрирует release в текущем Scope. release обязан возвращать эффект, а не void. В проекте: атом синхронизации вкладок в фазе 7 (подписка на событие storage).
Отложенное удаление (deferred removal)
Реестр не удаляет атом сразу при потере последнего подписчика, а ставит проверку на следующую задачу. Если за это время кто-то подписался снова, ресурс остаётся. Из-за этого под StrictMode подписка выполняется один раз. Подробности: урок 1.
Atom.keepAlive
Отключает удаление атома при отсутствии подписчиков. Значение живёт, пока живёт реестр.
useAtomMount
Hook, который держит подписку на атом без чтения значения. Нужен, чтобы ресурс внутри атома жил, пока смонтирован компонент.

Хранение: effect/unstable/persistence

KeyValueStore
Сервис с операциями get, set, remove над строками. Форма совпадает с localStorage. Реализации: layerMemory, layerStorage(() => localStorage). В проекте: todoRuntime.ts.
KeyValueStore.toSchemaStore(store, schema)
Обёртка над строковым хранилищем: get возвращает Option<Type>, set принимает Type. Кодирование в JSON выполняется через схему. Ошибка get: KeyValueStoreError | SchemaError. В проекте: TodoRepository.layerKeyValueStore.
Option
Значение, которого может не быть: Some(value) или None. Option.getOrElse(() => fallback) разворачивает его. При разворачивании в пустой массив нужен явный тип, иначе выводится never[].

HTTP: effect/unstable/httpapi, effect/unstable/http

Контракт (HttpApi, HttpApiGroup, HttpApiEndpoint)
Одно значение с описанием всех эндпоинтов: путь, метод, схемы params, payload, success, error. Из него выводятся и обработчики сервера, и методы клиента. В проекте: todoApi в src/entities/todo/todoApi.ts.
params, payload, success, error
Части эндпоинта. params — параметры пути, запись полей. payload — тело запроса, только схема. success — схема ответа, по умолчанию 204 без тела. error — схема или массив схем объявленных ошибок.
HttpApiSchema.status(code)
Аннотация HTTP-статуса на схеме ошибки. Читается с той схемы, что передана в error. Аннотация на членах Schema.Union не учитывается. В проекте: Schema.Union([EmptyTitle, TitleTooLong]).pipe(HttpApiSchema.status(400)).
HttpApiBuilder.group
Слой с обработчиками одной группы. Компилятор проверяет, что реализованы все имена из контракта и что E обработчика входит в объявленные ошибки. В проекте: src/server/todo/todoHandlers.ts.
HttpRouter.serve
Превращает зарегистрированные маршруты в HTTP-приложение. Обработчики подаются до serve, сервисы для них после. Подробности: справочник HttpApi-сервер.
HttpApiClient.make / makeWith
Создание клиента из контракта. makeWith принимает подготовленный HttpClient (с retry и timeout) и baseUrl. Методы клиента несут объявленные ошибки плюс HttpClientError | SchemaError. В проекте: make в todoClient.ts.
HttpClient
Низкоуровневый сервис запросов, аналог fetch. FetchHttpClient.layer даёт реализацию для браузера. HttpClient.retry и HttpClient.transformResponse навешивают политику на все запросы. Не путать с: клиентом из HttpApiClient, у которого методы названы по контракту.
HttpClientError и причина TransportError
Ошибка слоя HTTP. Поле reason._tag различает случаи. TransportError — запрос не дошёл до сервера (сеть, DNS, отказ соединения). Только при нём безопасен повтор: сервер точно ничего не обработал.
Retry и Schedule.exponential
Повтор запроса по расписанию. Schedule.exponential("100 millis") удваивает паузу между попытками. Условие while ограничивает, какие ошибки повторять. В проекте: HttpClient.retry({ while, times: 3, schedule }) в todoClient.ts.
Effect.timeout и TimeoutError
Ограничение времени ожидания. По истечении эффект прерывается и завершается ошибкой TimeoutError. Запрос при этом мог быть уже обработан сервером, поэтому повторять его по таймауту нельзя без идемпотентности.
Идемпотентность (idempotency)
Свойство операции: повторное выполнение с теми же аргументами даёт то же состояние. toggle с явным completed идемпотентен, create нет. В проекте: эндпоинт toggle принимает payload: { completed } вместо инверсии на сервере.
Порт-сервис (TodoClient)
Сервис с методами в терминах домена (create(title), toggle(id, completed)), который прячет форму HTTP-запросов и транспортную политику. Атомы зависят от него, а не от HttpApiClient.
HttpApiTest.groups
Клиент для теста, который вызывает обработчики напрямую, минуя сокеты, но через те же схемы.
OpenApi.fromApi
Описание контракта в формате OpenAPI. В тесте по нему проверяются пути, методы и статусы.
CORS
Правило браузера: страница с одного origin не получает ответ с другого без разрешающих заголовков от сервера. В проекте сервер добавляет их, потому что Vite и Node-сервер работают на разных портах.

Параллельность

Effect.forEach(items, f, { concurrency, discard })
Один эффект над коллекцией. По умолчанию последовательно. concurrency: n держит не больше n дочерних fiber одновременно, "unbounded" запускает все сразу. discard: true возвращает void. В проекте: clearCompletedAtom в todoStore.ts, concurrency: 3.
Fail-fast
Поведение Effect.forEach и Effect.all при ошибке: первая ошибка прерывает остальные запущенные fiber, и весь эффект завершается этой ошибкой. Не путать с: Promise.all, который отклоняется, но остальные промисы продолжают выполняться.
Effect.all
То же для фиксированного набора эффектов (кортеж или объект), результат сохраняет форму.
Semaphore
Ограничитель одновременного доступа, который можно разделить между разными вызывающими. Нужен, когда ограничение должно действовать на все вызовы, а не на один forEach.
Race condition (гонка)
Результат зависит от порядка завершения параллельных операций. В проекте: две вкладки сохраняют весь список целиком, и последняя запись затирает первую.

Архитектура проекта

Домен (domain) и инфраструктура (infrastructure)
Домен — правила и типы задачи (types.ts, todoRules.ts). Инфраструктура — способы хранения, сети, времени (todoRepository.ts, todoClient.ts). Стрелка импорта идёт от инфраструктуры к домену и никогда обратно.
Use case
Операция уровня приложения: берёт данные из репозитория, применяет правило домена, сохраняет. В проекте это функции createTodo, toggleTodo, renameTodo, removeTodo в src/server/todo/todoService.ts.
Репозиторий (repository)
Сервис доступа к данным с операциями в терминах домена: all, save. Реализации меняются на границе runtime, вызывающий код не меняется.
Слои папок: entities, features, pages, shared, server
entities/todo — типы, контракт, клиент, атомы данных. features/todos — сценарии UI: hooks и компоненты. pages — сборка страницы. shared/ui — компоненты без знания о todo. server — только серверные модули.
Обобщённый helper (higher-order helper)
Функция, принимающая шаг (input) => Effect<A, E, R> и обобщённая по E и R. Без обобщения все вызывающие получают объединение всех ошибок. В проекте: updateTodos в todoService.ts.

Справочники: ядро Effect, атомы и React, жизненный цикл атома, HttpApi-сервер. Уроки: 3. Повторение фаз 1–9.
